# PRO-014F2 提案：個人空間的 Pro 呈現

> 狀態：提案（只寫文件），等待擁有者決定 §9。排行榜的 Pro 光環與標記已由 PRO-014F1 完成（#253、#255）。

## 1. 結論

- 建議先做 **F2A：只顯示的身分標記**，不碰經濟、不新增素材、不改資料庫：
  - 個人空間頁頂端的狀態列與首頁 Orbit Window 標題旁，放一個小的「✦ Pro」標記（沿用 PRO-014F1 的樣式與各主題的文字顏色）；
  - Orbit 夥伴在 Pro 開始的那一天說一句中性的話，**不推銷、不提價格、不倒數**；結束時建議不說話（§5.2、§9.3）。
  - Pro 狀態一律讀「知道／不知道」的版本：還不確定時（快取過期、剛登入）標記不顯示、夥伴不說話，避免付費使用者被說成「結束了」。
- Pro 專屬的外觀內容（新的房間風格、夥伴形象或主角服裝）列為 **F2B（選做）**：只限新增的內容，現有的免費內容永遠不鎖；要做時另寫素材提案。
- **不建議**讓 Pro 影響進度（多金幣、專案加速、額外房間）：違反個人空間「真實行動優先」與「每個獎勵有清楚來源」的原則（§3.2 第 1、2 點），也會讓排行榜失去可比性。

## 2. 現況（2026-11-19 的 main）

- **個人空間 V2 沒有任何 Pro 的呈現**：
  - 個人空間頁的狀態列只有等級、金幣、Momentum 與待揭曉事件（`pages/personalSpaceV2.js` 的 `pageMarkup()`）；
  - Orbit Window 的標題列只有 Momentum（`personalSpace/v2/ui/orbitWindow.js`）。這個標題列在首頁（`home-window`）與個人空間頁的世界、編輯模式（`full-world`、`edit`）都會畫出來。
- **Pro 的判定**：
  - 大多數 gate 讀 `storage.isProUser()`（server 的 `my_pro_status()` 投影，PRO-014B／H）；設定頁另外用 `isPaidProUser()`／`isTrialUser()`；排行榜用 `get_leaderboard()` 回傳的 `is_pro`。
  - `storage.isProUser()` 在投影不存在（例如剛登入、登出時已清掉）或已超過 24 小時時都回傳 false——它分不出「不是 Pro」與「還不知道」。換日用的 `getProRolloverStatus()`（`proRollover.js`）在 server 模式（production）會回傳 `pro`／`not-pro`／`unknown`：沒有投影、投影屬於別的帳號、超過 24 小時或時鐘倒退、或取得時有效但已過了結束時間，都是 `unknown`；legacy 模式（回退用）只有 `pro`／`not-pro`。
  - server 的 `is_pro_active()` 把**試用期也算 Pro**（011、018），排行榜的 `is_pro` 也是。
- **已有的 Pro 功能**：主題（SUB-06）、保護卡（SUB-09）、歷史深度（SUB-05）、Focus Timer Pro、匯出、稱號模板、月報、排行榜光環與標記（PRO-014F1）。`tests/unit/proGateCallSites.test.js` 逐一列出 `storage.isProUser()` 的呼叫位置（總數 17）。
- **個人空間的原則**（`docs/personal-space-v2-product-spec.md` §3.2）：真實行動優先（1）；每個獎勵有清楚來源（2）；夥伴的話不得羞辱、威脅或情緒勒索（5）。
- **付費的原則**（`docs/monetization.md`）：降級後不顯示恐嚇性警告，只說「以下功能在 Pro 中提供」；免費版永不過期，資料永不刪除。
- **可用的外觀**（全部免費）：
  - 5 套房間風格：藍色工作室（預設）、明亮北歐、日式和風、夜貓工作室、深木書房；每套房間各有 6 件裝飾；
  - 兩種畫風：全 Q 版、全像素；
  - 主角與夥伴形象：Q 版各 6 種，像素版各 7 種（含 PS-242 的經典）。

## 3. 目標與不做的事

- **目標**：
  - Pro（含試用，§9.5）使用者在自己的空間裡看得到身分，和排行榜一致；
  - 不讓非 Pro 使用者覺得被比下去或被催促；
  - 只是顯示：不改獎勵、金幣、專案、Momentum，也不回寫任何 entitlement。
- **不做**：
  - 鎖住任何現有的免費內容；
  - 夥伴推銷 Pro、提價格或倒數；
  - 新增資料庫欄位或 RPC（F2A 不需要）；
  - 在個人空間顯示「升級」按鈕（升級入口維持在設定頁）。

## 5. 建議的第一階段：F2A（A1 ＋ A2）

### 5.1 身分標記（A1）

- **位置**：
  - 個人空間頁的狀態列，在「等級 N」之後；世界與編輯模式都顯示；
  - 首頁 Orbit Window 的標題列，在 Momentum 之前，**只在 `renderMode === 'home-window'`**（個人空間頁的 Orbit Window 不畫，否則同一頁出現兩次）。
- **來源**：`getProRolloverStatus(ownerId)`（`proRollover.js`，既有 export）。只有 `pro` 才顯示；`not-pro` 與 `unknown` 都不顯示。不寫進 V2 state、不進 reward ledger。
- **樣式**：沿用 `.pro-badge--inline` 與 PRO-014F1 收尾後各主題的 `--on-primary`。注意狀態列的 `.personal-space-v2-hud-stats span`（`style.css`）比 `.pro-badge--inline` 更具體，會蓋掉背景、文字色、邊框與內距：要用更具體的選擇器（例如 `.personal-space-v2-hud-stats .personal-space-v2-pro`）把這幾項都設回標記的樣式，並以 e2e 讀實際的計算樣式確認背景是主色、文字是 `--on-primary`（`badgeContrast` 測試只檢查主題變數，抓不到這種覆蓋）。沒有動畫。
- **無障礙**：`aria-label="Orbit Pro 會員"`；只是狀態，不可點。
- **訪客**：不顯示。

### 5.2 夥伴的話（A2，文案需核准）

| key | 何時 | 建議文案 |
|---|---|---|
| `companion.pro.started` | 這個帳號在這台裝置從「不是 Pro」變成「是 Pro」的那一天（付費、連勝解鎖、邀請解鎖；試用見下） | 「Pro 已開啟。這裡的一切照舊，你累積的每一步都算數。」 |
| `companion.pro.ended`（建議不用，§9.3） | 從「是 Pro」變成「不是 Pro」的那一天 | 「這個空間和你累積的一切都還在，我也還在。」 |

- 文案保持中性：多數 Pro 的開始不是付款（每個新使用者都有試用，另有連勝解鎖與邀請解鎖），所以不說「謝謝你支持」。
- **新帳號的試用多半聽不到**：開機時 `startTrial()` 與重新整理在第一次畫面之前完成（`app.js`），第一次記錄就已是 `pro`，依「第一次記錄不說」的規則不會說；只有試用在某次啟動之後才開始（例如離線時 `startTrial()` 沒成功、之後的啟動才成功）時才會說。
- **狀態判斷**：用 `getProRolloverStatus()`。`unknown` 時**不說話也不記錄**；只有已知的 `pro`／`not-pro` 才和上次比較。
- **記錄**：每個帳號在這台裝置記一筆 localStorage `orbit_ps_pro_seen:<帳號>` = `{ status, changedOn }`。
  - 第一次記錄（沒有舊值）只記下 `status`、`changedOn` 留空，不說話，避免舊使用者更新後突然收到；
  - 已知的狀態和上次不同時，記下新的 `status` 與 `changedOn = 今天`（以 app 的有效日期為準）；
  - `status === 'pro'` 且 `changedOn` 是今天時，夥伴的訊息換成這句；隔天自動回到一般的訊息。同一天又變回 `not-pro`（不說結束的話）時回到一般的訊息。
- **覆寫點**：夥伴的訊息來自 `buildPersonalSpaceV2Snapshot()` 裡的 `getCompanionReaction()`（`viewModels.js`），首頁與個人空間頁都經過它。
  - 讀寫 localStorage 與 Pro 狀態的部分（`proPresence.js`）在頁面（`home.js`、`personalSpaceV2.js`）算好，當成一個輸入傳給 builder；builder 只套用，維持純函式（許多單元測試直接 import `viewModels.js`）。
  - 覆寫只換 `dialogueKey`，所有顯示位置都經 `getCompanionDialogue()` 取文字；夥伴的 `state`、動畫與 `worldAction` 不變，夥伴引擎本身也不改（維持確定性）。
  - 這樣首頁卡片與點擊的提示、個人空間的卡片、dock 與詳情面板都會一致。
- **優先順序**：這句比揭曉事件、關係升階、專案完成等句子低；那些在的時候不覆寫。
- **語氣規則**（個人空間 §3.2 第 5 點）：不提價格、不提「升級」、不倒數試用天數、結束時不說「失去」。
- **不影響**：獎勵、揭曉事件、關係階段（AI-202）都不變。

### 5.3 授權與安全（PRO-014F 的完成條件）

- 兩者都是**純顯示**：沒有新增任何有價值的資料、API 或操作，不需要 server 端強制。交付時在 PR 與 `tasks.md` 列出新的 Pro 判斷位置（狀態列標記、Orbit Window 標記、夥伴的覆寫，共 3 處）。
- 這 3 處用 `getProRolloverStatus()`，不新增 `storage.isProUser()` 呼叫；若實作改用 `storage.isProUser()`，要更新 `proGateCallSites` 的清單與總數（目前 17）。
- 文字都是固定字串（不含使用者輸入），不需要額外的 escaping。

### 5.4 INFRA-105

- 判斷「今天要不要說」與讀寫本機記錄放在新模組（例如 `personalSpace/v2/proPresence.js`），**加進 `sw.js` 的 SHELL 清單**；既有的 SHELL 模組只 import 它的新 export。文案加在 `companionDialogue.js` 的表裡（既有 export，只多了 key）；`getProRolloverStatus` 是既有 export。

## 6. 後續（選做）：F2B Pro 專屬外觀

只有擁有者想要時才做，另寫素材提案。先定的規則：

- **只限新增的內容**：現有的房間風格、裝飾、畫風、主角與夥伴形象全部維持免費。
- **選擇器**：Pro 內容在 Edit Mode 的「風格、房間、裝飾與角色」裡顯示，非 Pro 時加上鎖定樣式。點了之後要做什麼需要決定：只說明「這個外觀在 Pro 中提供」（建議，個人空間不放升級入口），或照 SUB-04 跳出升級邀請卡。
- **降級**：選擇保留在 V2 state（不刪），場景改顯示預設；重新成為 Pro 時恢復。不顯示警告（付費原則）。
- **授權**：PRO-014F 規定有價值的東西要由 server 判斷。外觀若只在 client 判斷，任何人改本機程式就能解鎖（repo 是公開的）；若要防止，素材要放在私有 bucket 並由 server 授權下載。這需要擁有者明確選擇。
- **成本（估計）**：
  - 一件房間裝飾 ≈ 2 畫風 × 日夜 × 5 套房間風格 = 20 張渲染與擺放；
  - 一套房間風格 ≈ 房間 ＋ 8 件家具 ＋ 6 件裝飾，各 × 2 畫風 × 日夜，再加 2 張縮圖 ≈ 62 張；
  - 一種夥伴形象 ≈ 2 畫風 × 6 個狀態 = 12 張；一套主角服裝 ≈ 2 畫風 × 6 個動作 × 2 個朝向 = 24 張（角色沒有日夜版本）。

## 7. 驗收（F2A）

- Pro、試用、過期、免費、訪客，以及「不知道」（投影過期、剛登入）六種狀態下，個人空間狀態列與首頁 Orbit Window 的標記顯示正確；個人空間頁只出現一個標記。
- 標記在各主題的實際計算樣式：背景是主色、文字是 `--on-primary`（e2e 讀 computed style）。
- 夥伴的話：
  - 已知的「不是 Pro → 是 Pro」當天說 `started`，隔天不再說；
  - 「不知道」不說也不記錄，之後回到「是 Pro」不會被當成新的開始；
  - 第一次記錄不說；換帳號各自記錄；
  - 有揭曉事件、關係升階、專案完成時不覆寫；
  - 首頁卡片、提示與個人空間的卡片、dock、詳情面板一致。
- 沒有任何獎勵、金幣、專案數字因 Pro 改變（既有的 reward 測試不變）。
- e2e：Pro 與免費各一，截圖確認首頁卡片沒有擠壓（320px 寬）。

## 8. 風險與已知限制

- **狀態不確定**：投影超過 24 小時（例如隔了一天才打開）或剛登入時，狀態是「不知道」：Pro 使用者在重新整理完成前看不到標記，夥伴也不說話。這比說錯話好；重新整理通常在開啟後幾秒內完成。
- **試用結束的觀感**：試用期算 Pro 時，每個新使用者在第 15 天會看到標記消失。這是一個「失去」的訊號；因此建議結束時夥伴不說話（§9.3），只是標記不再顯示。
- **多台裝置**：夥伴的話以「這台裝置上次看到的已知狀態」判斷，每台裝置各說一次。
- **首頁空間**：Orbit Window 標題列在 320px 寬時已有 Momentum；放不下時改成只顯示「✦」並保留 `aria-label`。

## 9. 需要擁有者決定

1. **範圍**：F2A（A1 ＋ A2，建議）／只做 A1（標記）／F2A 並規劃 F2B／都不做（只保留排行榜）。
2. **標記位置**：個人空間狀態列 ＋ 首頁 Orbit Window（建議）／只有個人空間頁。
3. **夥伴的話**：只在開始那天說 §5.2 的 `started`（建議）／開始與結束都說／修改文案／不說話。
4. **Orbit Window 光暈（A3）**：不做（建議，首頁卡片的焦點留給專案進度）／做。
5. **試用期**：顯示為 Pro（建議，和排行榜一致；接受第 15 天標記消失，§8）／只有付費才顯示（排行榜的 `is_pro` 也要一起考慮是否一致）。
6. **F2B**：先不做（建議）／要做，並決定：先做哪一類與素材預算（§6）、點鎖定內容時的行為、是否接受只在 client 判斷。
